# v0.7 "Feel Good Update" 設計仕様

**ドラフト日**: 2026-04-21
**対象**: PixelColoringGame (Pixel Bloom) v0.7

---

## 1. Context

PixelColoringGame は SwiftUI/SwiftData 製の癒し系ピクセル塗り絵ゲーム。
直前の v0.6 で「Suno 音声10クリップの統合」と「Monthly Daily イベントの再設計」という**基盤側の大きな投資**を完了した。
次のアップデート v0.7 は、その基盤の上に乗る**プレイヤー体験の質の底上げ**を目的とする。

3つの Explore 監査で以下の改善機会が明確化された:

- **ゲーム盤**: 毎タップが同じ強度のハプティック、セル塗りのマイクロアニメーションゼロ、完了画面は音のみで視覚的祝福が弱い
- **ナビ/ビジュアル**: 新規シートでのテーマ迂回、ボタン装飾のコピペ、ローカライズ漏れ、タブ切替の視覚フィードバック欠如
- **進捗/達成**: 章クリアが静かに終わる、ストリーク・累計・初パーフェクト・Journey完走・Monthly完走のマイルストーン演出が皆無

本仕様は上記のうち「**プレイヤーが直接感情として受け取る体験**」に集中投資する(Approach A: Feel Good)。デザインシステム整備(Approach B)は v0.8 に分離する。

## 2. Goals / Non-Goals

### Goals

- 毎タップ/毎完了で受ける感覚体験を底上げする(Layer 1: 常時触覚・視覚層)
- レベル完了、章クリア、Journey完走、Monthly完走に**文脈に応じた祝福儀式**を提供する(Layer 2)
- これまで見過ごされていた**節目(マイルストーン)**を、二度とない体験として祝う(Layer 3)
- 全演出で **Reduce Motion / Low Power Mode** を一貫してサポートする
- M1 は**単独リリース可能**な粒度に切り、段階的に価値を届けられる構造にする

### Non-Goals

- デザインシステム整備(ハードコード値のテーマ化、ボタン統一、HomeBadgeLabel柔軟化、ローカライズ漏れ回収) — v0.8 行き
- 新規コンテンツ(章、レベル、音源、アート)の追加
- シェア/エクスポート/ソーシャル機能
- 祝福演出のユーザー側OFFスイッチ(設定画面)— v0.8以降で検討
- `JourneyCompleteView` 内の「この旅で達成したこと」統合表示 — v0.8 以降

## 3. Feature Layers

### Layer 1: 常時触覚・視覚層

プレイヤーが毎タップ感じる演出。ROI最大。

- **セル塗りアニメ**: 正解タップで scale pop (1.0→1.12→1.0、0.25s) + opacity fade-in
- **ハプティック階層化**: 5段階(`cellFill`軽 / `colorComplete`中 / `levelComplete`強 / `chapterClear`notif success / `milestone`軽notif)。`milestone` は `firstPerfect` / `streak:*` / `levels:*` の各トースト登場時に発火
- **パレット色完了演出**: 色完了時にチップが scale+glow、完了 tint へ滑らかに移行
- **ヒントセル識別演出**: ヒント塗布セルだけ pulse(光って自己主張)
- **間違いタップ**: 既存の offset shake に加え、短く柔らかい error tone(AudioPlayerService経由)

### Layer 2: 完了儀式アップグレード

- **レベル完了**: `CompletionView` カスケード登場(bg→artwork→rank→stats→CTA が0.15sずらし) + `ParticleEmitterView(.confetti)` オーバーレイ
- **章クリア専用画面**: 新規フルスクリーン `ChapterClearView`(章バッジ大表示 + 次章アンロック告知)
- **Journey完走画面**: 一度きりのフルスクリーン `JourneyCompleteView`(修了証的演出)
- **Monthly完走画面**: 31/31達成時のフルスクリーン `MonthlyCompleteView`(月のテーマ絵で締め)

### Layer 3: マイルストーン演出(トースト)

- **初パーフェクト**: 専用トースト(4.0s)
- **ストリーク**: 7日/14日/30日達成時のトースト(3.5s)
- **累計レベル**: 10 / 50 / 100 達成時のトースト(3.0s)

### 中核コンポーネント

**`CelebrationEvent` (enum, Identifiable, Hashable)**

| Event | priority | seenKey | supersedes |
|---|---:|---|---|
| `journeyComplete` | 100 | `journeyComplete` | `chapterClear:*`, `firstPerfect`, `levels:*`, `streak:*`, `monthlyComplete:*`(全吸収) |
| `monthlyComplete(ym)` | 90 | `monthlyComplete:2026-04` | `firstPerfect`, `levels:*`, `streak:*`(配下マイルストーン吸収) |
| `chapterClear(id)` | 80 | `chapterClear:berry-meadow` | — |
| `firstPerfect` | 70 | `firstPerfect` | — |
| `streak:30` | 62 | `streak:30` | `streak:14`, `streak:7` |
| `streak:14` | 61 | `streak:14` | `streak:7` |
| `streak:7` | 60 | `streak:7` | — |
| `levels:100` | 52 | `levels:100` | `levels:50`, `levels:10` |
| `levels:50` | 51 | `levels:50` | `levels:10` |
| `levels:10` | 50 | `levels:10` | — |

`supersedes` はワイルドカード(`chapterClear:*`)対応。`Coordinator` がパターンマッチで除去する。

**`CelebrationDetector` (純関数)**

```swift
enum CelebrationTrigger {
    case levelCompleted(LevelID, rank: Rank)
    case dailyCompleted(date: Date)
    case appLaunched
}

struct CelebrationDetector {
    static func detect(
        trigger: CelebrationTrigger,
        profile: PlayerProfileSnapshot,
        seen: Set<String>
    ) -> [CelebrationEvent]
}
```

**トリガー別検知許可リスト**:
- `.levelCompleted`: chapterClear, journeyComplete, firstPerfect, levelCountMilestone
- `.dailyCompleted`: monthlyComplete, streakMilestone, firstPerfect, levelCountMilestone
- `.appLaunched`: **streakMilestone のみ**(完了時発火系の二重検知を仕様で排除)

**冪等性の約束**: 同一 (trigger, profile, seen) → 同一結果。副作用なし、外部時刻/乱数なし。

**`CelebrationCoordinator` (ObservableObject)**

- `handle(trigger:)` → `Detector.detect()` → `enqueue()`
- `enqueue`: priority降順ソート、`supersedes` ワイルドカード適用で除去
- `@Published currentFullScreenEvent: CelebrationEvent?`
- `@Published currentToast: CelebrationEvent?`(fullScreen と toast は別スロット)
- 同一 `seenKey` の重複 enqueue は無視
- **`seenKey` は `currentEvent` セット時点で即保存**(クラッシュ耐性)
- `isCompletionFlowActive: Bool` — CompletionView を消さずに祝福チェーンを消化するための信号

**`CelebrationFlowState` vs `CelebrationCoordinator` の責任分離**

- `CelebrationCoordinator`: **アプリ全体**の祝福キュー、優先度整列、スロット管理、`seenKey` 永続化
- `CelebrationFlowState`: **CompletionView 内部**のローカル演出ステート(カスケード何段目か、confetti発火済みか、Next CTAの有効化タイミング)。あくまで `CompletionView` 配下のローカルVM

**`ParticleEmitterView`**

- `Canvas` + `TimelineView(.animation)` ベースの SwiftUI 製
- プリセット: v0.7 スコープは **`.confetti` のみ**実装。`.sparkle` / `.petals` は将来拡張の余地として API 設計上の配慮は残すが、v0.7 では実装しない(過剰実装回避)
- SpriteKit 非依存(依存を増やさない)
- Low Power Mode で particle 数 1/3 または完全スキップ
- Reduce Motion ON で静的バッジ+glow(アニメなし)

**`AnimationProfile` (3段階仕様)**

「完全削除はしない」。Reduce Motion の意味論(Apple HIG)は「激しい動きを減らす」であって「全アニメ削除」ではない。

| 通常 | Reduce Motion ON |
|---|---|
| セル塗り 0.25s scale pop | 0.1s opacity fade(scale無し) |
| パレット色完了 scale+glow | 0.15s tint 変化のみ |
| Cascade entrance(stagger) | 全要素同時 0.2s fade-in |
| Particle confetti | 静的バッジ+glow |
| ChapterClear badge bounce | 固定表示 + checkmark fade-in |
| ハプティック全段階 | ハプティック全段階(動きではない) |

API 例:
```swift
AnimationProfile.current.pop()             // → 通常時 .spring(...) / RM時 .easeOut(0.1)
AnimationProfile.current.cascadeDelay(i)   // → 通常 0.15*i / RM時 0
AnimationProfile.current.shouldShowParticles // → Bool
```

### データモデル拡張

`PlayerProfileStore`(SwiftData):

```swift
@Attribute var celebrationsSeenData: Data = Data()

var celebrationsSeen: Set<String> {
    get {
        (try? JSONDecoder().decode(Set<String>.self,
                                   from: celebrationsSeenData)) ?? []
    }
    set {
        celebrationsSeenData = (try? JSONEncoder().encode(newValue)) ?? Data()
    }
}
```

**カンマ区切りではなく JSON Data を採用する理由**: 将来のキーにコロンやカンマが混入しても壊れない、破損データは空 Set フォールバックで安全。

### 音声マッピング(既存10クリップ流用)

| 場面 | 既存クリップ |
|---|---|
| セル塗り | (無音) |
| 色完了 | 無音でスタート(下記注記参照) |
| レベル完了 | Level Complete |
| 章クリア | Chapter Clear |
| Journey完走 | Chapter Clear + Badge 合成 |
| Monthly完走 | Event Complete |
| ストリーク | Daily Streak |
| 初Perfect | Badge |

**新規音源は作らない**。既存枠で運用。

**色完了音の判断プロセス**: M1 は**無音でリリース**する(デフォルト OFF)。調整コストが低く、連続発火時の「うるささ」リスクをゼロに保てる。M1 の QA 時に複数名から「物足りない」「色完了に気付きにくい」等のフィードバックが出た場合に限り、M2 段階で Level Complete 軽量版(音量 -6dB 相当)を追加する判断をする。最初から音を付けるより、必要と判明してから足すほうが調整コストが低い。

## 5. Data Flow

### 全体フロー

```
トリガー(3箇所)
  ①GameSessionStore.finishLevel
  ②DailyExperience.commitToday
  ③AppView.onAppear
        ↓
CelebrationDetector.detect(trigger, profile, seen)
        ↓ [CelebrationEvent]
CelebrationCoordinator.enqueue
  ・priority降順ソート
  ・supersedes ワイルドカード適用で除去
  ・currentEvent セット時点で seenKey を保存
        ↓
AppView ルート:
  .fullScreenCover(item: currentFullScreenEvent)
  .overlay(MilestoneToastHost(toast: currentToast))
        ↓
dismiss → coordinator が次の event を出すか、queue 空ならフロー終了
```

### シナリオ1: 普通のレベル完了(節目なし)

`CompletionView` 登場(カスケード+confetti)→ Detector 該当なし → ユーザー "Next" タップで次レベルまたは章ホーム。

### シナリオ2: 章の最終レベル + Journey完走 + 初Perfect + 100本目

Detector 候補 → priority ソート → **supersedes 適用後、`[journeyComplete]` のみに収束**(Journeyが全部吸収)。
提示順: CompletionView → "Next" → `JourneyCompleteView`(手動 dismiss 必須)→ フロー終了。

**吸収されたイベントの seenKey は保存される**ので、将来二度と発火しない(Journey完走の意味論と整合)。

### シナリオ3: アプリ起動時、前日プレイで7日ストリーク達成

`detect(.appLaunched)` は streak のみ拾う設計により `[streak:7]` を検出 → Title→Home 遷移後に `MilestoneToastHost` がトーストを上から降ろす → 3.5s auto-dismiss、`streak:7` 保存。

### シナリオ4: Monthly完走(31/31日目のDaily完了)

`detect(.dailyCompleted)` の結果、仮に `levels:50` や `streak:*`、`firstPerfect` が同時発生していても、`monthlyComplete` が supersedes で配下マイルストーンを吸収。候補は **`[monthlyComplete:2026-04]`** のみに収束。
提示順: CompletionView(Daily版) → `MonthlyCompleteView` → フロー終了(トーストなし)。

吸収されたマイルストーンの `seenKey` は保存されるため、将来二度と発火しない(Journey完走と同じ意味論を Monthly にも適用。感情曲線逆行を回避)。

**CTA動的切替**: `MonthlyCompleteView` の CTA は `CatalogService.isReleased(nextYearMonth)` で分岐:
- 次月リリース済 → `"Next Month →"`、タップで Daily タブへ遷移
- 未リリース → `"Continue"`、タップで dismiss して元画面に戻る

### CompletionView → fullScreenCover 遷移の「中間画面」回避

**方針**: `CompletionView` を祝福チェーン消化中は**dismiss しない**。

```
CompletionView (base、dismissされない)
  └ User taps "Next"
    └ coordinator.currentFullScreenEvent が non-nil なら:
      └ CompletionView 上に .fullScreenCover で祝福View を重ねる
      └ CompletionView は裏で生き続ける(JourneyHomeView が一瞬も見えない)
    └ 祝福View dismiss 後、次 event が出るか、queue 空なら CompletionView も一緒に dismiss
```

`CompletionView` の `isPresented` を `coordinator.isCompletionFlowActive` にバインドし、`Coordinator` が完全終了を宣言した時のみ解除する。

### トースト連続提示ルール

| 属性 | 値 |
|---|---|
| 1件表示時間 | `firstPerfect: 4.0s`, `streak: 3.5s`, `levels: 3.0s` |
| 連続間フェード | 0.3s |
| **合計上限** | **8秒**。超過する3件目以降は**省略(UI非表示、ただし `seenKey` は保存)** |
| タップ挙動 | 即 dismiss、次トーストへ進む |
| スワイプ上 | 即 dismiss |
| 下画面操作 | 可能(トースト背景 `.allowsHitTesting(false)`) |
| 重ね合わせ | なし(直列提示のみ) |

## 6. 主要設計決定の再掲

1. `journeyComplete` / `monthlyComplete` が配下マイルストーンを supersede(感情曲線逆行を回避)
2. `celebrationsSeen` は `Data` 型 + computed `Set<String>`
3. `detect(.appLaunched)` は streak のみ検知
4. `seenKey` は表示開始時に保存(クラッシュ耐性)
5. CompletionView は祝福チェーン消化中 dismiss しない(中間画面回避)
6. `MonthlyCompleteView` CTA は次月リリース状況で動的切替
7. トースト合計8秒上限(超過分は省略、seen保存のみ)
8. 章アンロックバナーは `ChapterClearView` に一本化、"unlocked event title" は残す
9. `CelebrationDetector` は純関数、冪等性保証
10. `AnimationProfile` は3段階(通常/Reduce Motion で最小feedback/完全削除はしない)

| `CelebrationDetector` | トリガー別許可リスト遵守、冪等性(同入力→同出力)、境界条件(streakDays 6→7 で発火、7→7 で発火しない)、levels:100 到達時に levels:10/50/100 全候補が返ること、trigger=.appLaunched で firstPerfect が返らないこと |
| `CelebrationCoordinator` | priority 降順ソート、`supersedes` ワイルドカード除去(`chapterClear:*` が全章を消す)、`journeyComplete` が全低優先を吸収、同一 seenKey の二重enqueue防止、表示開始時に seen 保存 |
| `PlayerProfileStore.celebrationsSeen` | Data ↔ Set<String> 往復で情報欠損なし、破損データ投入時に空 Set フォールバック |
| `AnimationProfile` | reduceMotion=true で `pop()` が opacity fade のみ返すこと、cascadeDelay(i) が 0 になること、shouldShowParticles=false |
| `CelebrationFlowState` | Next タップ後、coordinator に pending event がある間 `isPresented=true` を維持し、queue 空になった時のみ false に遷移すること |

### 統合テスト / 実機QA(UI Testing の限界を踏まえた現実的方針)

**UI Testing の原理的限界**: `fullScreenCover` 遷移は ~0.35秒で、`XCUIElement.exists` のスナップショットでは中間状態を確実に捕まえられない。

そのため以下の二本立て:

- **option 1 (自動)**: View 層の重ね順検証ではなく、**`CelebrationFlowState` と `CelebrationCoordinator` の state 遷移をユニットテストで検証**する。「CompletionView の `isPresented` は queue 消化中は false にならない」を **state レベル**で証明。
- **option 2 (手動)**: 「中間画面(JourneyHomeView)が一瞬も見えないこと」の視覚確認は **M2/M3 の QA項目として実機目視で確認**。必要に応じて画面録画を残す。

### 手動QA(DebugMenu 活用)

- 各 `CelebrationEvent` の手動発火で見た目とアニメ確認
- Reduce Motion ON/OFF の全イベント確認
- Low Power Mode でパーティクル軽量化確認
- ハプティック5段階の差が体感できるか(実機必須)
- SwiftData マイグレーション実機(M2完了条件)

**DebugMenu アクセス**: Title 画面 version ラベルを **2.0秒長押し** + 成功ハプティック通知で遷移。`celebrationsSeen` 全クリア等の破壊的操作は**確認ダイアログ**を挟む(「全ての祝福記録を消去します。本番データでは戻せません。」→ Cancel / Confirm)。**`seenKey` 個別クリア機能**も搭載し、QA シナリオで「特定の祝福を未体験状態に戻す」操作を可能にする(例: `streak:*` だけクリアして「seen空から一気に30日達成」の真の supersedes 挙動を検証)。リリースビルドは `#if DEBUG` で完全除外。

### パフォーマンスリグレッション

- Instruments で `PixelBoardView` at 4.0x zoom のフレームレートを **M1改修前後で比較**、60fps 維持が M1 完了条件
- `ParticleEmitterView` 稼働中の CPU 使用率を iPhone SE 2nd で計測、**30% 未満を目標**(M2完了条件)

## 9. Risks & Mitigations

| リスク | 緩和策 |
|---|---|
| SwiftData マイグレーションで既存ユーザプロファイル破損 | `celebrationsSeenData` はデフォルト `Data()` で追加、デコード失敗時 empty Set フォールバック。**M2完了条件で M1→M2 マイグレーション実機検証必須** |
| `ParticleEmitterView` 性能問題 | Instruments 計測を M2 完了条件に含める、Low Power Mode 対応と particle数削減を内蔵。性能未達時は M3 に一部倒す |
| 章アンロックバナー削除による情報欠損 | 削除前に `CompletionView` の "unlocked event title" との分離を確認、テストで event title が章クリア後も表示されることを検証 |
| M1 単独リリース時の中途半端感 | M1完了条件に他者体感評価とパフォーマンス数値を明記、感覚判断を排除 |
| `seenKey` 表示開始時保存により、表示前にアプリkillされると二度と出ない | 祝福イベントは装飾的で実害なし。逆に「表示された後に kill → 次回再表示」の二重表示リスクを防ぐほうが重要 |
| `journeyComplete` 吸収によるマイルストーン喪失感 | 吸収された `seenKey` は保存される(二度と発火しないので論理的整合)。Journey完走という一度きりの最大演出に全てを集約する意図を仕様として明言 |
| トースト連続で画面上部を占領 | 合計8秒上限、3件目以降は省略(seen保存のみ)で上限保証 |
| DebugMenu 誤操作による進捗消失 | 2秒長押し+ハプティック通知でアクセス認知、破壊操作は確認ダイアログ |

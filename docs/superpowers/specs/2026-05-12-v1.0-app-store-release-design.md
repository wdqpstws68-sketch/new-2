# Pixel Bloom v1.0 App Store リリース 設計仕様

**ドラフト日**: 2026-05-12
**対象**: PixelColoringGame (Pixel Bloom) v1.0 (App Store 初回リリース)
**前提仕様**: `2026-04-21-v0.7-feel-good-update-design.md` (v0.7 Feel Good Update)

---

## 1. Context

PixelColoringGame は SwiftUI + SwiftData 製の癒し系ピクセル塗り絵ゲーム「Pixel Bloom」。
v0.6 までで 486 レベル/Suno 音声 10 クリップ/Monthly Daily イベント等の主要機能を実装済み。
v0.7「Feel Good Update」の詳細設計は `2026-04-21-v0.7-feel-good-update-design.md` に完了済みだが未実装。

本仕様は **App Store 初回リリース (v1.0)** を完成形と定義し、以下を全て満たした状態にすることを目的とする:

- v0.7 Feel Good Update の M1/M2/M3 すべてを実装
- iPhone/iPad universal 対応
- AdMob バナー広告本番化 + ATT + Privacy Manifest 一式
- Bundle ID / 署名 / Team ID 等のリリース設定
- 2 言語 (日本語/英語) のストア提出物
- GitHub Pages ホスト型のプライバシーポリシー/サポートページ
- TestFlight Internal クローズドテストを経た上で本番審査提出

## 2. Goals / Non-Goals

### Goals

- App Store で v1.0 として **公開可能な品質** で初回リリースする
- v0.7 Feel Good Update の全演出を v1.0 に含めて、初回プレイ体験を最高水準にする
- バナー広告で **持続可能な無料モデル** を確立し、UX を損なわない配置に限定する
- 4 デバイス幅 (iPhone 6.7", iPhone 6.5", iPad 13", iPad 12.9") × 2 言語 のストア提出物を整える
- Apple 審査の **2 大棄却原因**(プライバシー不備、Made for Kids 誤分類による広告違反)を回避する

### Non-Goals

- 課金 (IAP)、リワード広告、インタースティシャル広告 — v1.0 後の検討
- Made for Kids カテゴリ参入 — v1.0 では 4+ 一般カテゴリ
- 8 言語ストア展開 — v1.0 は jp/en のみ。Localizable.xcstrings は 8 言語維持
- Push 通知、CloudKit 同期、共有/エクスポート — v1.0 範囲外
- 完全な独自ドメイン化 (pixelbloom.app) — v1.0 後の検討
- 新規コンテンツ (章、レベル、音源、アート) の追加

## 3. Release Phase Architecture

リリースまでを 4 フェーズに分解、それぞれ完了条件を持つ。前フェーズの完了条件未達では次フェーズに進まない。

```
Phase 1: v0.7 Feel Good 実装 (~6-8日)
  M1 触覚底上げ → M2 完了儀式中核 → M3 マイルストーン演出
  完了条件: v0.7 仕様書の各M完了条件 + 既存テスト全 green
        ↓
Phase 2: リリース技術準備 (~6-8日)
  Bundle ID / Team / 署名 / AdMob 本番化 / Privacy Manifest /
  ATT / iPad 対応 / WIP Home redesign 仕上げ
  完了条件: 実機 (iPhone SE 2nd + iPhone 15 + iPad) でビルド・起動・主要動線確認
        ↓
Phase 3: ストア提出物・公開ページ (~3-4日)
  GitHub Pages の Privacy/Support ページ、ASC レコード、
  スクリーンショット 4 デバイス × 2 言語 = 8 セット、説明文 jp/en
  完了条件: App Store Connect で「Submit for Review」ボタンが押せる全準備完了
        ↓
Phase 4: TestFlight → 提出 → 公開 (~2 週間)
  Internal Test → 問題対応 → 提出 → Apple 審査 → Release manually
  完了条件: 「Ready for Sale」ステータス到達
```

**累計目安**: 実作業 17-20 日 + TestFlight 観察 1 週間 + Apple 審査 1-3 日。

### 5.2 Info.plist 拡張

追加するキー (現状からの差分のみ):

```xml
<!-- ATT (App Tracking Transparency) -->
<key>NSUserTrackingUsageDescription</key>
<string>Pixel Bloom はあなたに合わせた広告を表示するためにこの許可を求めます。許可しなくてもアプリは通常通り使えます。</string>

<!-- AdMob 本番 App ID (Apple 提出時の placeholder ではない。実 ID を取得して入れる) -->
<key>GADApplicationIdentifier</key>
<string>ca-app-pub-XXXXXXXXXXXXXXXX~YYYYYYYYYY</string>

<!-- 暗号化輸出コンプライアンス (HTTPS 標準利用のみで該当) -->
<key>ITSAppUsesNonExemptEncryption</key>
<false/>

<!-- SKAdNetwork IDs を AdMob 公式リストの全件 (約 100 件) に拡張 -->
<key>SKAdNetworkItems</key>
<array>
  <!-- 既存 3 件 + AdMob 公式 SKAdNetwork ID 一覧の追加分 -->
</array>
```

**`NSUserTrackingUsageDescription` の文言は審査で読まれる**。「広告のため」をぼかさず、許可しないでも動くことを明示する。

**`GADApplicationIdentifier`**: 現状はテスト ID `ca-app-pub-3940256099942544~1458002511` が入っている。AdMob 管理画面で本番 App を作成し、本番 App ID に置き換える。テスト ID のままで提出するとリジェクト or 公開後 0 円。

**`SKAdNetworkItems`**: AdMob 公式ドキュメントの最新リスト全件を反映 (https://developers.google.com/admob/ios/quick-start の付属ファイル)。本仕様承認後、Phase 2 着手時に最新版を引いて反映する。

### 5.3 Privacy Manifest (PrivacyInfo.xcprivacy)

iOS 17 から App Store 提出に Privacy Manifest が事実上必須。新規ファイル `PixelColoringGame/PrivacyInfo.xcprivacy` を作成し、以下を宣言:

- **NSPrivacyTracking**: `true` (AdMob 経由でトラッキングする可能性)
- **NSPrivacyTrackingDomains**: AdMob のトラッキングドメインリスト (`googleadservices.com`, `doubleclick.net` 等)
- **NSPrivacyCollectedDataTypes**:
  - `Other Diagnostic Data` (AdMob 経由)
  - `Device ID` (AdMob 経由、トラッキング目的)
  - `Product Interaction` (AdMob 経由、アプリ機能のため)
- **NSPrivacyAccessedAPITypes**: SwiftData/UserDefaults 利用に伴う `CA92.1` (UserDefaults) 等、Apple の 4 カテゴリ Required Reason API ごとに正当な reason を選択

**Reason 選択は推測ではなく、`grep` で UserDefaults や FileTimestamp API の使用箇所を確認した上で決定する**。

### 5.4 iPad 対応

SwiftUI ベースなのでレイアウトは多くがそのまま動くが、以下を Phase 2 完了条件として検証する:

| 検証項目 | 対象画面 | 期待動作 |
|---|---|---|
| PixelBoardView 縦長すぎ問題 | Play | iPad で盤面が画面中央に配置され、上下余白が確保される。盤面サイズは画面短辺 80% を上限 |
| Home redesign の HStack/VStack | Home | iPad では `NavigationSplitView` 化せず、iPhone と同じ縦スタックで OK。ただし最大幅を 600pt 程度に絞り中央配置 |
| パレットトレイ | Play | iPad で横に伸びすぎない (最大 600pt 中央) |
| Journey/Collection/Daily | 各タブ | グリッドが iPad で適切に列数増 (`LazyVGrid` の minimum を活かす) |
| 横画面 | 全画面 | iPad のみ横画面を許可。iPhone は縦のみ維持 (LSRequiresIPhoneOS は維持) |
| AdMob バナー | Home, Collection | iPad では `GADAdSizeLeaderboard` (728x90) 自動選択、iPhone では `GADAdSizeBanner` (320x50) |

iPad 専用のレイアウト分岐が必要な箇所は `@Environment(\.horizontalSizeClass)` で `.regular` を判別して切り替える。

### 5.6 AdMob SDK 統合

**SDK 追加**: Swift Package Manager で `https://github.com/googleads/swift-package-manager-google-mobile-ads-ios` を追加。バージョンは Phase 2 着手時の最新安定版を採用。

**初期化** (`PixelColoringGameApp.swift` の `init`):

```swift
GADMobileAds.sharedInstance().start(completionHandler: nil)
```

**ATT 要求** (`AppView.onAppear` 直後、最初のフレーム描画後):

```swift
if #available(iOS 14, *) {
  ATTrackingManager.requestTrackingAuthorization { _ in
    // 結果に関わらず広告は表示する (非追跡広告にフォールバック)
  }
}
```

ATT ダイアログは **アプリ起動 1 回目に表示する** 設計とし、Apple HIG に従い「許可しないでも動く」ことをユーザーが理解できる文言にする (上記 NSUserTrackingUsageDescription)。

**バナー配置**: 新規 SwiftUI Wrapper `AdBannerView` を `PixelColoringGame/Features/Ads/` に作成。`GADBannerView` を `UIViewRepresentable` でラップ。配置場所:

| 画面 | 配置 |
|---|---|
| HomeView | 一番下、safeAreaInset(bottom) |
| CollectionBookView | 一番下、safeAreaInset(bottom) |
| Play 画面 (PlayView/GameView) | **広告なし** (集中体験を守る) |
| Journey/Daily 一覧 | **広告なし** (v1.0 では Home/Collection のみ。様子を見て v1.1 で拡張) |
| CompletionView, 祝福系 View | **広告なし** |
| TitleScreenView | **広告なし** |

### 5.7 ホーム再デザイン WIP の取り扱い

現状 7a027e3 で home redesign skeleton が commit され、未コミット差分が複数ファイルに残る。Phase 2 で以下を判断:

### 6.3 スクリーンショット仕様

App Store は **4 デバイス幅** で各 3 枚〜10 枚のスクリーンショットを要求 (一部の幅は他幅から自動派生)。v1.0 では以下を必須準備:

| デバイス | 解像度 | 言語 | 枚数 |
|---|---|---|---|
| iPhone 6.7" (iPhone 15 Pro Max) | 1290×2796 | ja, en | 5 枚 ×2 |
| iPhone 6.5" (iPhone 11 Pro Max) | 1242×2688 | ja, en | 5 枚 ×2 (6.7" から自動派生でも可、確実なら個別撮影) |
| iPad Pro 13" (M4) | 2064×2752 | ja, en | 5 枚 ×2 |
| iPad Pro 12.9" (3rd-6th gen) | 2048×2732 | ja, en | 5 枚 ×2 |

**5 枚の構成案** (1 枚目が最重要、App Store 検索結果で最初に見える):

1. **タイトルカット**: アプリ名 + キャッチコピー「やさしい色で、心ほどける時間。」+ ホーム画面のヒーローカード
2. **塗り絵プレイ中**: PixelBoardView at 中ズーム、パレットトレイが見える、色を塗っている瞬間
3. **完成の瞬間 (祝福)**: v0.7 の confetti + ChapterClearView または CompletionView のカスケード
4. **コレクション**: 並んだ完成済みピクセルアート、達成感を伝える
5. **デイリーチャレンジ**: Monthly カレンダー、ストリーク表示

**撮影方法**: Xcode のシミュレータで `Cmd+S` で PNG 取得。各シミュレータは ASC が要求する正確な機種で行う。

スクリーンショット内に **キャッチコピーを焼き込む** 場合、jp/en で別ファイル必要。本仕様では:

- **方針 a (推奨)**: 1 枚目のみキャッチコピーを焼き込み (2 言語別)、2-5 枚目はそのまま (キャプションは ASC 側)
- 方針 b: 全 5 枚にコピー焼き込み (作業重い、後回し可)

2. Organizer > Distribute App > App Store Connect > Upload
3. ASC で Build が processing 完了 (約 15-30 分)
4. Build に Export Compliance を回答 (`ITSAppUsesNonExemptEncryption=false` 設定済みなのでスキップ)

**Internal Testers**:

- TeamMembers (最大 100 名、Apple Developer 登録者) を Internal Testers に追加
- 本人 + 身近な人 1-3 名 (Team Members として ASC に招待)
- TestFlight Build を配布、最低 1 週間のテスト期間を取る

**テストプロトコル**:

| テスト | 内容 |
|---|---|
| Cold start | 起動時のクラッシュなし、ATT ダイアログ表示確認 |
| 主要動線 | Home → Play → Completion → Home のループを 5 回 |
| 章クリア | v0.7 ChapterClearView の表示確認 |
| Journey 完走 | DebugMenu で疑似的に達成、JourneyCompleteView 表示確認 (Internal Build なので DebugMenu 有効) |
| Monthly 完走 | DebugMenu でテスト、MonthlyCompleteView 表示確認 |
| Streak/Milestone | DebugMenu でストリーク 7/14/30 を再現、トースト表示確認 |
| Reduce Motion | 設定でオン、全祝福演出を確認 |
| Low Power Mode | オン、パーティクル軽量化確認 |
| 広告表示 | ホーム/コレクションで AdMob テスト広告表示 (本番出荷前は test ad unit 使用) |
| 広告クリック | クリック → Safari 遷移 → 戻る → 状態維持 |
| ATT 拒否時 | 拒否選択でも広告は出るがパーソナライズなしを確認 |
| バックグラウンド復帰 | 数時間後復帰でクラッシュなし、状態保持 |
| デバイス回転 (iPad) | 縦/横で UI 破綻なし |

**判断**: 1 週間で重大クラッシュ 0 件、UI 破綻 0 件であれば Phase 4.2 (本番審査提出) へ。

### 7.2 本番審査提出

**Submit for Review 前の最終チェックリスト**:

- [ ] AdMob unit ID を **テスト ID から本番 ID に切替済み**
- [ ] DebugMenu が Release ビルドで除外されていることをコード grep で確認 (`#if DEBUG` 囲い込み)
- [ ] Privacy Manifest の `NSPrivacyTracking=true` が ATT 実装と整合
- [ ] Info.plist の `NSUserTrackingUsageDescription` が日本語で自然
- [ ] スクリーンショットに **テスト広告のラベル「Test Ad」が映り込んでいない**
- [ ] 1024×1024 のマーケティングアイコンに透明 / 角丸 / アルファチャンネルがない
- [ ] Apple 連絡先 (審査時の質問用メールアドレス) 設定済み

**Submit**:

- ASC > App Store > Build を Phase 4.1 でテスト済みの Build に紐付け
- すべての必須セクションが緑チェック
- Submit for Review

**審査期間**: Apple 公式は 24-48 時間。経験的には 1-3 日。

**棄却された場合の対応**:

- Resolution Center で reviewer からの指摘内容を確認
- 修正 → 新規 Build をアップロード → Resubmit
- リジェクト常連項目を Risks セクションに先回り記述

### 7.3 公開

**Release Type**: **Manually release this version** を選択 (推奨)。
これにより Apple 審査 PASS 後にすぐ公開されず、ユーザーが「Release」を押したタイミングで App Store に並ぶ。SNS 告知、ブログ、その他コミュニケーション準備の時間を確保できる。

**公開タイミング**: 任意。本人が「Release」ボタンを押す。

### 7.4 Phase 4 完了条件

- App Store Connect 上で App ステータスが「Ready for Sale」に到達
- App Store で `Pixel Bloom` を検索して自分のアプリが表示される (公開後最大 24h 反映ラグあり)
- 初回ダウンロード成功確認

## 9. Testing Strategy

### ユニットテスト

v0.7 仕様書の「8. Testing Strategy」を全部採用し、本仕様で追加:

| テスト対象 | 内容 |
|---|---|
| `AdBannerView` | iPhone/iPad で異なる adSize を返すこと、初期化失敗で空 View にフォールバック |
| `ATT request` | 起動 1 回目に呼ばれること、結果に関わらずアプリは継続 |
| Bundle ID 検証 | `Bundle.main.bundleIdentifier == "com.pixelbloom.app"` を CI で確認 |

### Snapshot Test (任意・推奨)

iPad/iPhone の両方で主要画面の SwiftUI スナップショットを記録、レイアウト破綻を CI で検知。v1.0 ではマストではないが、Phase 2 着手時に導入余地を判断。

### 手動 QA (Phase 4.1)

§7.1 のテストプロトコル全項目。DebugMenu (Internal Build のみ) を活用し、本来は数週間プレイしないと見れない祝福を瞬時に呼び出す。

### 審査リジェクト予防 QA

- スクリーンショット内に「Test」「Debug」「Mock」表記が映り込んでいないか目視
- ATT ダイアログの NSUserTrackingUsageDescription を実機で読み、自然か確認
- アプリ説明文に他社商標 (Suno, AdMob, Apple, Google 等の言及) を必要最小限に
- Privacy Manifest の declared APIs と実際のコードが整合
- アプリ起動直後の AdMob 初期化失敗時もクラッシュしないことを実機確認

## 10. Risks & Mitigations

| リスク | 確率 | 緩和策 |
|---|---|---|
| AdMob ATT 関連で審査リジェクト (NSUserTrackingUsageDescription 不適切) | 高 | 文言を Apple HIG に厳密準拠、許可しないでも動くことを明示 |
| Privacy Manifest の宣言漏れで審査リジェクト | 中 | Apple 公式の Required Reason API リストを `grep` で全件確認、宣言する |
| AdMob テスト ID 残しで提出 | 高 | Phase 4.2 のチェックリストで明示、コード grep で `3940256099942544` を検索 |
| iPad レイアウトが致命的に崩れる | 中 | Phase 2 で iPad シミュレータで全画面確認、必要に応じて `horizontalSizeClass` で分岐 |
| TestFlight Internal Test で発見される重大バグ | 中 | 1 週間の観察期間を必ず確保、Phase 4.1 完了条件 |
| Apple 審査で 1-2 回リジェクトされる | 中 | スケジュールに 1 週間のバッファを内包、リジェクト対応をワークフローに織り込む |
| v0.7 実装で予期せぬ性能問題 | 中 | v0.7 仕様の Instruments 計測完了条件を厳守、未達なら ParticleEmitter を simplify |
| ホーム redesign WIP が中途半端で v1.0 出荷 | 中 | Phase 2 開始時に「仕上げる/退避」を明示判断、判断結果を本仕様の Phase 2 補足に追記 |
| Made for Kids 自動分類で広告制限 | 低 | カテゴリを「ゲーム > パズル/カジュアル」に固定、Made for Kids = No を明示 |
| 自宅 Wi-Fi での AdMob テスト広告ロード失敗 | 低 | 4G/5G 接続のサブテストを Phase 4.1 で含める |
| 1024×1024 アイコンに alpha チャンネルが残っている | 低 | 提出前に `sips -g hasAlpha` で確認 |
| App Store キーワード重複制限 | 低 | jp/en それぞれ 100 字制約内、本仕様の例を流用 |

## 11. Verification (End-to-End)

最終的に **下記すべてを満たしたら v1.0 リリース完了** とする:

1. App Store Connect で `Pixel Bloom` のステータスが「Ready for Sale」
2. App Store iPhone/iPad アプリで `Pixel Bloom` 検索 → アプリページが表示
3. 自分のデバイスで App Store からダウンロード → 起動 → ATT ダイアログ → ホーム画面到達
4. AdMob バナーが実機で表示
5. レベルクリア → 完成画面 → 祝福演出が v0.7 仕様通り動作
6. Privacy Policy URL を Safari で開ける
7. Support URL を Safari で開ける
8. App Store のページに掲載されているスクリーンショットが想定通り表示
9. ASC ダッシュボードに初回インストール数 ≥ 1 が記録される

## 13. Key Design Decisions (再掲)

1. v1.0 = v0.7 Feel Good 全実装 + リリース必須項目。ホーム redesign WIP は退避を許容
2. Bundle ID は `com.pixelbloom.app` (ブランド風、個人情報非露出)
3. AdMob はバナーのみ、ホーム/コレクション下部限定、Play 中は表示なし
4. Made for Kids = No、年齢区分 4+
5. ストア提出物は ja/en の 2 言語、Localizable.xcstrings は 8 言語維持 (アプリ内 UI)
6. iPad は universal 対応するが iPad 専用 UI は最低限 (中央寄せ・最大幅制限のみ)
7. TestFlight Internal Test を最低 1 週間挟む
8. 「Manually release this version」で公開タイミングをコントロール
9. 4 フェーズで完了条件ゲートを設け、前フェーズが完了するまで次へ進まない
10. Privacy/Support は GitHub Pages で無料ホスティング、独自ドメインは v2.0 以降
